# multi-post – פוסט אחד, כל הרשתות

**העיקרון:** אף פעם לא מפרסמים בשם הארגון בלי אישור מפורש של המשתמש על הנוסח הסופי של כל רשת. בלי אישור – רק DRY RUN.

## איך זה בנוי

```
קובץ + טקסט בסיס
      │
      ▼
התאמה לכל רשת (Claude)  ──►  אישור המשתמש
      │
      ├─► Postiz (השרת של הארגון) ─► אינסטגרם · פייסבוק · טיקטוק · X · יוטיוב · לינקדאין · טלגרם
      └─► ערוץ וואטסאפ: חבילה מוכנה (אין API לערוצים) – המשתמש לוחץ "שלח"
```

- **Postiz** באחסון עצמי. ההקמה החד-פעמית: `references/SETUP.md`.
- **הסקריפט:** `scripts/postiz.mjs` (Node 20+, בלי תלויות).
- **כללי הכיתוב וההגדרות לכל רשת:** `references/platforms.md`. לקרוא לפני כל התאמה.
- **הדף לטלפון:** "מרכז הפרסום" – https://claude.ai/artifact/BzCcLuBQjE5KhyMEJhjJaf (המקור: `artifact/publish-hub.html`; לעדכן עם `Artifact` + `url`). המשתמש מעלה קובץ וטקסט, Claude שבדף מתאים לכל רשת, המשתמש מאשר, והפוסט נכנס לתור (`db`, אוסף `jobs`). את התור מפרסמים מכאן (סעיף ד).

## משתני סביבה (לעולם לא בקובץ – הריפו ציבורי)

| משתנה | ערך |
|---|---|
| `POSTIZ_URL` | כתובת ה-backend **כולל `/api`**, למשל `https://social.example.org/api` |
| `POSTIZ_API_KEY` | ב-Postiz: Settings ← Public API |

- **מקומית:** משתני סביבה.
- **בסשן ענן:** `request_credential` ל-host של השרת. הכותרת היא `Authorization` עם המפתח עצמו. אם Postiz דוחה את הקידומת `Bearer`, לשמור את המפתח בהגדרות הסביבה (Network secrets) בלי קידומת. את `POSTIZ_URL` (לא סוד) מעבירים ב-`export` בפקודה.
- אם השרת לא נגיש מהענן (הודעת proxy "no rule allows host") – `get_environment` ואז `update_environment` להוספת ה-host בלבד.

## א. "תעלה את זה לכל הרשתות"

1. **לאסוף:** הקובץ (וידאו או תמונה; מ-koach-reel, מהמשתמש או מנכס בארטיפקט), טקסט בסיס או נושא, לאילו רשתות (ברירת מחדל: כל מה שמחובר, `node scripts/postiz.mjs channels`), ומתי (עכשיו או שעה).
2. **לבדוק מדיה** מול `platforms.md`: טיקטוק ויוטיוב רק וידאו; ריל 9:16; אורך. עם `ffprobe` כשיש.
3. **להתאים כיתוב לכל רשת** לפי `platforms.md`: אורך, טון, האשטגים, קישור, כותרת ליוטיוב ולטיקטוק. בעברית, "כח התערבות" בלי ו'. לא להמציא עובדות, מספרים או ציטוטים.
4. **להציג למשתמש** טבלה: רשת | נוסח | תווים/מגבלה. לשאול עם `AskUserQuestion`: "לפרסם / לתקן / לתזמן".
5. **לכתוב job** בתיקיית scratchpad (לא בריפו) לפי `templates/job.example.json`.
6. **DRY RUN:** `node scripts/postiz.mjs post job.json`. לתקן כל "Problems".
7. **רק אחרי אישור:** `node scripts/postiz.mjs post job.json --yes`.
8. **לוודא:** אחרי דקה-שתיים `node scripts/postiz.mjs status`. לדווח קישור לכל רשת (`releaseURL`), ולכל `ERROR` את הסיבה ומה עושים.
9. **ערוץ וואטסאפ:** לתת את הנוסח בבלוק להעתקה, ואת הקובץ עצמו (`SendUserFile`), עם הוראה: וואטסאפ ← עדכונים ← הערוץ ← 📎 ← הקובץ ← להדביק ← שלח. בטלפון, בדף מרכז הפרסום יש כפתור "שתף" שפותח את הוואטסאפ עם הקובץ והטקסט.

## ב. תזמון
`"when": "2026-12-01T19:30:00+02:00"` (שעון ישראל, עם offset). הסקריפט ממיר ל-UTC. Postiz מפרסם בעצמו בזמן, גם כשהסשן סגור.

## ג. "מה עלה?" / "למה זה נכשל?"
`node scripts/postiz.mjs status 7`. שגיאות נפוצות:
- `Refresh channel needed` – החיבור פג. להתחבר מחדש לרשת בממשק של Postiz.
- טיקטוק/יוטיוב עלו "פרטי" – האפליקציה עוד לא עברה audit (ראו SETUP). לשנות ידנית לציבורי באפליקציה.
- `unaudited_client_can_only_post_to_private_accounts` – אותה סיבה בטיקטוק.

## ד. "פרסם את מה שבתור" (מהדף בטלפון)
1. `ArtifactData` → `query` על אוסף `jobs` בארטיפקט מרכז הפרסום (הכתובת למעלה), `status == "approved"`.
2. לכל job: להוריד את קובץ המדיה (`Artifact` action `read` עם `path` = מזהה הנכס) לתיקיית scratchpad, ולבנות job.json מהנוסחים **כפי שאושרו בדף** (לא לנסח מחדש).
3. DRY RUN, ואז `--yes` (האישור כבר ניתן בדף; אם משהו השתנה, כמו נוסח שחורג ממגבלה, לשאול).
4. לעדכן את המסמך: `status: "published"` + `results` (רשת → קישור/שגיאה), או `status: "error"` + `error`.

## מה לא עושים
- לא מתחברים לוואטסאפ בכלים לא רשמיים (whatsapp-web.js, Baileys וכדומה) – זה מפר את תנאי השימוש ועלול לחסום את המספר של הארגון.
- לא שומרים בריפו מפתחות, קובצי מדיה, job.json או מזהי ערוצים.
- לא מפרסמים בלי אישור, גם אם זה "רק טלגרם".
